## 1. Graph (GraphQL)

**Что это.** Второй способ общения с сервером. В REST на каждое действие свой адрес (`/api/orders`, `/api/products`), и сервер сам решает, какие поля вернуть. В GraphQL адрес один (`/api/graphql`), а клиент сам пишет запрос и перечисляет нужные поля.

```graphql
{ orders { id title products { title price { symbol value } } } }
```

**Как устроено у нас.** REST остался (логин, пользователи, обратная совместимость), а данные (приходы, продукты, создание, удаление, фильтры) фронтенд теперь запрашивает через GraphQL. Реализован на `graphql-yoga`.

**Где.**
- `backend/src/graphql.ts` — схема (типы, запросы Query, изменения Mutation) и обработчики (resolvers). Защита та же, что в REST: изменения только с JWT, иначе код `UNAUTHENTICATED`.
- `frontend/src/api/client.ts` — функция `gql()` и запросы. Ошибки GraphQL (`UNAUTHENTICATED`, `BAD_USER_INPUT`, `NOT_FOUND`) переводятся обратно в тот же `ApiError`, поэтому остальной фронтенд не изменился.
- `backend/tests/api.graphql.test.ts` — 6 тестов.

**Для видео.** Откройте http://localhost:4000/api/graphql (песочница GraphiQL), выполните запрос выше. Покажите, что убрав поле из запроса, вы убираете его из ответа. Затем вкладка Network в браузере: запросы `graphql` вместо `orders`.

## 2. Web Workers

**Что это.** JavaScript в браузере однопоточный: тяжёлый расчёт «замораживает» страницу. Web Worker — отдельный поток, куда можно отдать расчёт и получить ответ сообщением. В React Native аналог — вынос работы из JS-потока в нативный модуль или отдельный поток.

**У нас.** Данные для диаграмм статистики (суммы по приходам, разбивка по типам) считает воркер.

**Где.**
- `frontend/src/workers/stats.worker.ts` — код воркера (получает приходы, возвращает данные для графиков).
- `frontend/src/hooks/useStatsData.ts` — хук: создаёт воркер, шлёт задачу, игнорирует устаревшие ответы (номер запроса). Если воркер недоступен, считает в основном потоке; под графиком написано, кто посчитал.

**Для видео.** Страница «Статистика»: внизу подпись «Данные посчитал Web Worker». DevTools → Sources → Threads/Workers показывает отдельный поток.

## 3. PWA

**Что это.** Сайт, который можно установить как приложение и который частично работает без сети. Нужны три вещи: манифест, иконки и service worker.

**Где.**
- `frontend/src/app/manifest.ts` — манифест (название, иконки, `display: standalone`), отдаётся как `/manifest.webmanifest`.
- `frontend/public/icon-192.png`, `icon-512.png` — иконки.
- `frontend/public/sw.js` — service worker. Страницы: сначала сеть, при ошибке — кэш, а если страницы в кэше нет — `offline.html`. Статика `/_next/static`: сначала кэш. Запросы `/api` и сокеты не кэшируются: данные всегда живые.
- `frontend/src/components/system/ServiceWorkerRegister.tsx` — регистрация, **только в production** (в режиме разработки кэш мешает видеть изменения).

**Как проверить (обязательно production):**

```bash
cd frontend && npm run build && npm start     # плюс бэкенд, например: cd backend && npm run start:memory
```

Откройте http://localhost:3000, пройдитесь по страницам. DevTools → Application → Service Workers (статус *activated*) и Manifest. Затем Network → Offline и обновите страницу: посещённые страницы откроются из кэша, новые покажут «Нет подключения». В адресной строке Chrome появится значок установки.

## 4. Event-Driven Architecture (EDA)

**Что это.** Вместо цепочки «сделал действие → сразу вызвал всех, кому это важно» код **публикует событие** («создан приход»), а заинтересованные части **подписаны** на него и реагируют независимо. Источник события ничего не знает о подписчиках.

**Событие → реакции у нас:**

```
REST или GraphQL меняет данные
        │ publish(order.created …)
        ▼
   шина событий (EventEmitter)
        ├─► аудит: строка в логе сервера (кто и что изменил)
        └─► Socket.io: рассылка 'domain-event' всем вкладкам
                                │
                                ▼
                браузер: LiveUpdates обновляет списки
```

**Где.**
- `backend/src/events.ts` — шина и аудит; события `order.created|deleted`, `product.created|deleted`.
- `backend/src/app.ts` и `graphql.ts` — публикуют события после успешных изменений.
- `backend/src/socket.ts` — подписчик, рассылающий события браузерам.
- `frontend/src/components/system/LiveUpdates.tsx` — подписка в браузере; с задержкой 150 мс запрашивает списки заново. Один сокет на вкладку (`frontend/src/realtime/socket.ts`).

**Для видео.** Откройте две вкладки (или два браузера). В одной добавьте приход — во второй он появляется без перезагрузки. В логе бэкенда видна строка аудита.

## 5. FrontEnd Optimization

**Что сделано и зачем:**

| Приём | Где | Эффект |
|---|---|---|
| Lazy Loading тяжёлых частей | диаграммы и карта через `next/dynamic` (`StatsLoader`, `MapLoader`), формы и попап в `OrdersView` | страница «Статистика» ~5.6 кБ собственного кода, Recharts подгружается отдельно |
| `React.memo` для строки продукта | `components/products/ProductRow.tsx` | при вводе в поиск не перерисовываются строки, у которых ничего не изменилось |
| `useDeferredValue` + `useMemo` | `OrdersView`, `ProductsView` | поле поиска отвечает мгновенно, фильтрация списка идёт с низким приоритетом и не пересчитывается без причины |
| Web Worker | см. п. 2 | расчёты не блокируют интерфейс |
| Кэш service worker | см. п. 3 | повторные визиты не качают статику заново |
| Дебаунс обновлений | `LiveUpdates` | пачка событий — один запрос |

**Измерить самому:**

```bash
npm run analyze    # из корня; после сборки откроется карта бандла (frontend/.next/analyze/)
```

В выводе `npm run build` смотрите колонку *First Load JS*: у каждой страницы свой размер, общая часть (~88 кБ) выделена отдельно.

## 6. Task Runners

**Что это.** Единая точка входа для рутинных команд, чтобы не помнить, в какой папке что запускать. Мы используем npm-скрипты, ничего ставить дополнительно не нужно.

**Корневой `package.json`:**

| Команда | Что делает |
|---|---|
| `npm run setup` | ставит зависимости backend и frontend |
| `npm run dev:mock` | запуск всего без Docker и БД (бэкенд в памяти + фронтенд) |
| `npm run dev:backend` / `dev:frontend` | отдельно, для работы с настоящей БД |
| `npm run build` / `analyze` | production-сборка / сборка с картой бандла |
| `npm run lint` | ESLint (`next/core-web-vitals`) |
| `npm run typecheck` | проверка типов TypeScript в обеих частях |
| `npm test` | unit и интеграционные тесты |
| `npm run test:e2e` | функциональные тесты (Playwright) |
| `npm run check` | линтер + типы + тесты одной командой (удобно перед коммитом и в CI) |
| `npm run up` / `down` | Docker Compose |

## 7. Интеграционные и функциональные тесты

Три слоя («пирамида тестов»):

| Слой | Что проверяет | Где | Скорость |
|---|---|---|---|
| Unit | отдельные функции: формат дат, суммы, поиск, валидация, JWT, редьюсеры | `frontend/tests/`, `backend/tests/validate.test.ts` | миллисекунды |
| Интеграционные | сервер целиком (supertest): вход, права, CRUD приходов и продуктов, каскадное удаление, фильтры, события, GraphQL | `backend/tests/api.rest.test.ts`, `api.graphql.test.ts` | секунды, без БД и без сети (репозиторий в памяти) |
| Функциональные (e2e) | настоящий браузер кликает по настоящему приложению | `frontend/e2e/app.spec.ts`, конфиг `frontend/playwright.config.ts` | десятки секунд |

e2e-сценарии (13): список приходов, сортировка приходов и продуктов, открытие и закрытие панели, «+» без входа ведёт на логин, неверный пароль, поиск, серверный фильтр продуктов, создание и удаление прихода после входа, статистика через Web Worker, манифест PWA, живое обновление между клиентами.

Почему интеграционные тесты быстрые и без БД: сервер работает через интерфейс `Repo` (`backend/src/types.ts`) с двумя реализациями — MySQL и память (`repo.memory.ts`). Тесты берут вторую. Тот же приём позволяет запускать `dev:mock` с настоящим бэкендом без базы.

Playwright сам запускает `npm run dev:mock` (`webServer` в конфиге). Первый раз нужен браузер: `cd frontend && npx playwright install chromium`.

## Что изменилось в запуске без Docker

Раньше `dev:mock` поднимал маленький отдельный файл-имитацию API. Теперь он запускает **настоящий бэкенд** с данными в памяти (`STORAGE=memory`): те же REST, GraphQL, JWT с bcrypt, WebSocket. Поэтому нужна установка зависимостей и в `backend`: `npm run setup` из корня делает обе.
