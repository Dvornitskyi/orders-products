# Видео-демонстрация (4–6 минут)

Задание: «Запишите короткое видео развёрнутого приложения, чтобы максимально отобразить реализованный функционал».
Значит: показываем **работающее приложение** (лучше на сервере, а не на localhost), код почти не открываем.

## Что сделать до записи

1. Запустить приложение (сервер или `docker compose up --build`) и открыть главную страницу.
2. Убрать мусорные данные: должны остаться исходные 3 прихода и 6 продуктов.
3. Подготовить в браузере две вкладки приложения и вкладку с `/api/graphql` (адрес бэкенда, порт 4000).
4. Для PWA запустить production-режим (`cd frontend && npm run build && npm start`): в `dev` service worker выключен.
5. Включить «Не беспокоить», увеличить масштаб браузера (⌘ +, 125%), закрыть лишние вкладки.
6. Запись: QuickTime (`⌘ + Shift + 5`) с микрофоном. Один раз прогнать без записи.

Вход: `admin` / `admin123`.

## Сценарий

Формат каждого шага: **Показать** → **Сказать** → *Как сделано* (для себя, если спросят; на видео достаточно одной фразы).

### 1. Вступление (15 сек)
**Показать:** главная страница, адресная строка.
**Сказать:** «Это приложение Orders & Products для учёта приходов и продуктов. Покажу весь функционал уровней Junior+ и Middle.»
*Как сделано:* Next.js (React, TypeScript) + Express + MySQL, всё в Docker.

### 2. Верхнее меню и навигация (30 сек)
**Показать:** дату и время вверху справа (идут в реальном времени), счётчик вкладок. Откройте вторую вкладку, счётчик растёт. Переключите страницы в боковом меню, видна анимация перехода.
**Сказать:** «Вверху время в реальном времени и счётчик активных вкладок. Он работает через WebSocket: открываю ещё одну, и число растёт.»
*Как сделано:* Socket.io: сервер считает подключения и рассылает число всем. Роутинг Next.js, анимация в `template.tsx`.

### 3. Приходы (1 мин)
**Показать:** список приходов, затем клик по приходу (открывается панель рядом), закрыть крестиком.
**Сказать:** «У каждого прихода название, число продуктов, дата в двух форматах и сумма в долларах и гривнах. По клику рядом открывается панель с продуктами, её можно закрыть.»
*Как сделано:* данные с сервера уже в первом HTML (SSR). Суммы считаются функцией `orderTotals` (покрыта тестами).

### 4. Права доступа и вход (30 сек)
**Показать:** нажмите «+»: перенос на страницу входа. Введите неверный пароль (ошибка), затем верный.
**Сказать:** «Смотреть можно без входа, изменять только после авторизации. Вход по логину и паролю, сервер выдаёт токен JWT.»
*Как сделано:* пароль хранится как хеш bcrypt, токен подписан на сервере и хранится в localStorage (Web Storage).

### 5. Создание и удаление (1 мин)
**Показать:** создайте приход (сначала сохраните пустую форму, видны ошибки). Добавьте продукт в приход. Удалите приход через попап подтверждения.
**Сказать:** «Формы проверяют данные: пустое поле даёт ошибку. Удаление идёт через подтверждение. Вместе с приходом удаляются его продукты.»
*Как сделано:* правила валидации лежат отдельно (`validation/`) и покрыты unit-тестами; на сервере те же проверки; в базе `ON DELETE CASCADE`.

### 6. Продукты, фильтры, поиск (45 сек)
**Показать:** страница «Продукты», выбор типа и спецификации, поиск в шапке.
**Сказать:** «Все продукты с гарантией, ценами в двух валютах и названием прихода. Есть фильтры по типу и по спецификации, а поиск работает по приходам и продуктам.»
*Как сделано:* фильтры уходят на сервер (GraphQL), поиск фильтрует уже загруженный список в браузере.

### 7. Язык (15 сек)
**Показать:** переключите RU → UA → EN.
**Сказать:** «Интерфейс на трёх языках, выбор запоминается.»
*Как сделано:* переводы в JSON-файлах, язык хранится в cookie, поэтому сервер сразу отдаёт нужный язык.

### 8. Статистика, карта, пользователи, настройки (45 сек)
**Показать:** по 10 секунд на страницу. На «Статистике» покажите подпись про Web Worker.
**Сказать:** «Статистика: суммы приходов и разбивка по типам. Карта с приходами. Пользователи видны после входа. В настройках язык и данные аккаунта.»
*Как сделано:* диаграммы Recharts подгружаются лениво; карта Leaflet; данные для диаграмм считает Web Worker.

### 9. Middle: реальное время (30 сек)
**Показать:** две вкладки рядом. Создайте приход в одной, во второй он появляется сам.
**Сказать:** «Это событийная архитектура: сервер публикует событие "создан приход", и все открытые вкладки обновляются сами.»
*Как сделано:* Event-Driven Architecture: шина событий на сервере, подписчики: аудит в лог и рассылка по Socket.io.

### 10. Middle: GraphQL (30 сек)
**Показать:** вкладка `/api/graphql`, запрос `{ orders { id title } }`, затем добавьте поле `products { title }`.
**Сказать:** «Данные приходят через GraphQL: клиент сам выбирает поля. Добавил поле, и ответ расширился, сервер менять не нужно.»
*Как сделано:* `graphql-yoga`; доступ к изменениям только с токеном, как и в REST.

### 11. Middle: PWA и оффлайн (45 сек)
**Показать:** DevTools → Application: Manifest и Service Workers (activated). Включите Offline, обновите страницу.
**Сказать:** «Приложение устанавливается как PWA. Без сети открываются уже посещённые страницы, для остальных показывается страница "Нет подключения".»
*Как сделано:* манифест, иконки, service worker с кэшем; запросы к API не кэшируются.

### 12. Тесты и запуск (30 сек, по желанию)
**Показать:** терминал, `npm run check` (зелёные тесты), `docker compose up`.
**Сказать:** «Есть unit, интеграционные и функциональные тесты, запуск одной командой через Docker.»
*Как сделано:* Vitest, supertest, Playwright; команды собраны в корневом `package.json`.

### 13. Финал (10 сек)
**Сказать:** «Код и инструкция по запуску в репозитории на GitHub. Спасибо!»

## Если спросят «как реализовано» (коротко)

- **Состояние:** Redux Toolkit. **Стили:** Bootstrap + БЭМ.
- **SSR:** страницы рендерятся на сервере с данными, затем «оживают» в браузере.
- **Безопасность:** bcrypt, JWT, SQL с параметрами.
- **Оптимизация:** ленивая загрузка, `React.memo`, `useDeferredValue`, Web Worker, кэш service worker.
- **Хранилище бэкенда:** интерфейс `Repo` с реализациями MySQL и «в памяти» (для тестов и быстрого запуска).
