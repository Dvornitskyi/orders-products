# Запуск без Docker и без базы данных

Самый быстрый способ посмотреть приложение. Данные хранятся в памяти, поэтому MySQL не нужен. Запуск через Docker с настоящей базой описан в [README.md](README.md).

## Что понадобится

- **Node.js 20.19 или новее** (проверка: `node -v`).
- **npm** (ставится вместе с Node.js; проверка: `npm -v`).
- Свободные порты **3000** (сайт) и **4000** (API).

## Шаг 1. Откройте терминал в папке проекта

```bash
cd orders-products
```

Дальше все команды выполняются из этой папки (там лежит `package.json` с командой `setup`).

## Шаг 2. Установите зависимости

```bash
npm run setup
```

Команда запускает `npm install` в `backend/` и в `frontend/`. Первый раз занимает 1–2 минуты. Сообщения вроде `npm warn deprecated` и `vulnerabilities` можно пропустить, `npm audit fix --force` запускать не нужно. Успех: команда завершается без `npm error`.

Без `npm run setup` то же делается вручную:

```bash
npm --prefix backend install
npm --prefix frontend install
```

## Шаг 3. Запустите приложение

```bash
npm run dev:mock
```

В одном терминале стартуют две программы:

1. **Бэкенд** (папка `backend/`) на порту 4000 с хранилищем в памяти (`STORAGE=memory`). Работают REST, GraphQL, JWT и WebSocket, как в боевом режиме.
2. **Фронтенд** (Next.js, папка `frontend/`) на порту 3000.

Готово, когда в терминале появились строки:

```
API listening on :4000 (storage: memory)
✓ Ready
```

## Шаг 4. Откройте приложение

Адрес: **http://localhost:3000**

Вы должны увидеть список из 3 приходов. Чтобы создавать и удалять данные, войдите: **логин `admin`, пароль `admin123`**.

## Шаг 5. Проверьте, что всё работает

| Что сделать | Что должно произойти |
|---|---|
| Открыть вторую вкладку с сайтом | Счётчик вверху вырос с 1 до 2 |
| Перейти в «Продукты» | Видно 6 продуктов, работают фильтры и сортировка |
| Нажать «+», войти, создать приход | Приход появился в списке |
| Открыть http://localhost:4000/api/orders | Приходы в формате JSON |
| Открыть http://localhost:4000/api/graphql | Песочница GraphQL (введите `{ orders { id title } }` и нажмите ▶) |

## Шаг 6. Остановите приложение

В терминале нажмите `Ctrl + C`. Данные в памяти пропадают: при следующем запуске снова будут исходные 3 прихода и 6 продуктов.

## Если что-то не работает

**Порт занят** (`EADDRINUSE` или сайт не открывается). Найдите и остановите процесс:

```bash
lsof -i :3000     # или :4000; в колонке PID номер процесса
kill <PID>
```

**`command not found: npm`.** Не установлен Node.js: скачайте с https://nodejs.org (LTS).

**Версия Node ниже 20.19.** Обновите Node.js или переключите версию (`nvm use 20`).

**Страница пустая или «Не удалось загрузить данные».** Бэкенд не запущен или упал: посмотрите вывод терминала, там будет причина. Попробуйте остановить (`Ctrl + C`) и запустить `npm run dev:mock` заново.

**Ошибка при установке зависимостей.** Удалите папки и поставьте заново:

```bash
rm -rf backend/node_modules frontend/node_modules
npm run setup
```

## Как это устроено

Фронтенд берёт данные из API. Чтобы не поднимать базу, бэкенд умеет работать с разными «хранилищами»: у него есть интерфейс `Repo` (`backend/src/types.ts`) и две реализации, `repo.mysql.ts` (боевая) и `repo.memory.ts` (в памяти). Выбор делает переменная `STORAGE`. Остальной код (маршруты, GraphQL, JWT, события) общий, поэтому в этом режиме приложение ведёт себя как настоящее. Единственное отличие: данные не сохраняются между запусками.
