# Этап 1 — только фронтенд (без Docker и без базы)

Нужен только Node.js 20.19+ (или 22+). Запуск:

```bash
cd frontend
npm install
npm run dev:mock
```

Откройте http://localhost:3000. Вход для создания и удаления: `admin` / `admin123`.

`dev:mock` запускает две вещи в одном терминале:
1. `mock/server.mjs` — маленький тестовый API на :4000 (данные в памяти, те же URL и тот же JSON, что у настоящего бэкенда).
2. Next.js фронтенд на :3000.

Остановка: `Ctrl+C`. После перезапуска данные возвращаются к начальным.
Счётчик активных вкладок (WebSocket) в этом режиме отключён: он заработает на этапе 2, когда появится настоящий бэкенд.

Этап 2: заменяем `mock/server.mjs` на `backend/` + MySQL (`docker compose up --build`). Фронтенд при этом не меняется.

## Что такое mock (тестовый API)

Фронтенд берёт данные из API. Настоящего сервера с базой на первом этапе ещё нет, поэтому `mock/server.mjs` его имитирует:
массивы данных в памяти + те же адреса (`/api/orders`, `/api/products`, `/api/auth/login` ...) и тот же формат JSON.
Посмотреть, что он отдаёт: `curl http://localhost:4000/api/orders` или вкладка Network в DevTools браузера.

Отличия от настоящего бэкенда: данные не сохраняются между запусками, пароль сравнивается как обычная строка (без bcrypt),
у токена фальшивая подпись (проверяется только срок действия).
